## 为什么改版（先说清楚，不藏）

v1 写死「总体 = OpenAlex 全部 4516 个 topic，不筛选不抽样」，理由是普查没有抽样误差。
写完之后、正式采数之前，**撞上一个我事先不知道的事实**：

**OpenAlex 已经不是免费不限量了。** 2026-08-24 实测服务端响应头与报错体：

```
x-ratelimit-limit-usd = 0.1        匿名档每日预算 $0.10
x-ratelimit-credits-required = 10  每次请求 10 credits = $0.001
→ 匿名免费额度实为 100 次/天，不是坊间说的 10 万次/天
本仓库 .secrets 里那把 key：每日 $1.00（1000 次）+ 预付 $2 + 一次性 20,000 credits
```

全总体普查需 4516 × 3 = **13,548 次 = $13.55**；只靠每日免费额度要 **14 天**，
而复赛截止 9/3。**所以改的是样本量，不是判断标准。**

## 抽样框与抽样方法（写死，抽之前）

- **抽样框** = 已冻结在盘的 `topics.json`，含全部 4516 个 topic。
  **sha256 = `7df1bf6f2a819bbbc9c22483894188e61384bcb69b63f6ce8802a2b29b2b15c9`**。
  它是 v1 阶段 A 真跑出来的全量（`meta.count` 4516 = 落盘 4516），不是本版新造的。
- **样本量 n = 1000**（占总体 22.1%），3000 次请求，落在现有额度内，不需要新充值。
- **抽法**：对抽样框**按 `id` 字典序排序后**，用固定种子的确定性 PRNG 做
  Fisher–Yates 洗牌，取前 1000 个。
  - **种子 = `trend-scale-v2-20260824`**（本文件写死，抽之前就固定）
  - PRNG = xmur3 派生种子 + mulberry32，实现在 `scale.mjs` 里，零依赖、跨机确定
  - **任何人拿这份 topics.json 加这个种子，必须复现出逐条相同的 1000 个 topic。**
    判据会重跑抽样并逐条比对；对不上即整轮作废。
- **先排序再洗牌**是承重步骤：`topics.json` 的原始顺序来自 OpenAlex 的分页游标，
  不保证稳定。不排序的话，别人重跑抽出来的就是另一批。

## 与 v1 相比，唯一实质变化：现在有抽样误差了

v1 写「普查没有抽样误差，不许给它套统计检验来显得更科学」。**抽样版这条必须反过来**：

- 报比例（如 `too_narrow` 占比、`ratio ≥ 1000` 占比）时，**必须同时给 95% 置信区间**，
  且**必须带有限总体校正**（FPC = √((N−n)/(N−1))，N=4516, n=1000）。
  不给区间就是把抽样结果当普查结果用。
- 报中位数/分位数时**不给区间**（分位数的区间需要额外假设，本轮不做），
  但必须在结论里注明「这是样本分位数，不是总体分位数」。

## 预测：**逐字沿用 v1 的 P1–P4，一个字不改**

```
P1  measured 的 ratio 中位数 ≥ 100
P2  measured 中 ratio ≥ 1000 的占比 ≥ 10%
P3  ratio 的 P95/P5 ≥ 10^4（跨 4 个数量级）
P4  too_narrow 占总体 < 30%
```

⚠ **必须披露的污染**：写本文件时，我**已经看过一次 20 条 topic 的冒烟结果**
（v1 阶段 B 的 `--limit 20`，用于验证脚本能跑）。那 20 条显示
`too_narrow 17/20 = 85%`、`measured 仅 3 条`、`P95/P5 = 7`。
按门捷列夫判据，**看过数据之后写的预测不算预测**。所以：

- **P1–P4 一个字不改**，仍按 v1 的原样评判 —— 它们确实写在任何数据之前。
- **不新增任何预测**。看过 20 条之后再补一条「我猜 too_narrow 会很高」，
  那不是预测，是抄答案。
- 冒烟那 20 条 topic **不从抽样框里剔除**（剔除会让样本不再是那个种子抽出来的），
  但它们的缓存会被复用，这不影响数字（同一 URL 同一答案）。
- 依常识，P3 与 P4 很可能被推翻。**推翻了就如实记账**——
  「本作品自己的预测被自己的数据推翻」正是这台仪器该有的产出，不是事故。

## 失败判据（整轮作废，退出码 2）

- 抽样不可复现：用写死的种子重跑抽样，得到的 1000 个 topic 与 `rows` 对不上
- 抽样框 sha256 与本文件写死的值不符（有人换过抽样框）
- `rows` 条数 ≠ 1000
- 单调性违反率 > 5%（口径语义理解错了）
- measured 中 ratio < 100 的比例为 0（指标无区分度）
- API 失败率 > 5%
- 统计量与逐条原始数据对不上
- 报了比例却没给带 FPC 的置信区间

## 诚实边界（必须与结论一起出现）

沿用 v1 全部四条，**并追加两条**：

- **这是 22.1% 的随机样本，不是普查。** 所有比例都带抽样误差，区间必须与点估计同时出现。
- **改版动机是预算，不是数据。** 改的是样本量，判断标准与预测一个字没动；
  v1 与本文件都在盘上，任何人可以逐行 diff 出到底改了什么。
