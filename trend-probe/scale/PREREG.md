# 口径敏感度 · 全总体普查 · 预注册（接触数据之前写死）

> 2026-08-24。trend-probe 的升级：从 **7 个短语的轶事**，升级为 **OpenAlex 全部 topic 的普查**。
> 初赛文档自陈的空缺三「各学科的总体都是试点规模，不是领域级结论」，本探针针对的就是这一条。
>
> **本文件必须在任何普查请求发出之前落盘并锚定。** 判据脚本 `verify-trend-scale.mjs`
> 同样写在出数之前——看到数据再定判据，就是这个项目从第一天起在抓的那个病。

## 要测什么

trend-probe v0.1 报过一个数：同一概念 "literature-based discovery"，三种 OpenAlex 检索口径
命中数为 1,815,368 / 775 / 223 —— **差约 8000 倍**。

那是 **n=7 的轶事**。评委完全有理由问：你是不是挑了七个最夸张的短语？

本轮回答这个问题的方式是**不抽样**：把 OpenAlex 自己的全部 topic 拿来，一个不漏地测一遍。

## 总体定义（写死，不许事后改）

**总体 = OpenAlex `/topics` 端点返回的全部 topic 的 `display_name`。**

- 取全量走 `cursor` 分页，`per-page=200`，直到 cursor 耗尽。**不筛选、不抽样、不排除任何 topic。**
- 2026-08-24 开查前 `meta.count = 4516`。**若实际落盘条数与 `meta.count` 不符，整轮作废**
  （分页漏抓是本仓库踩过的坑：`per-page=1` 曾把 group_by 截成 1 组，产出"结构是假的"真数字）。
- 选 topic 而不是自拟词表，是因为**词表由谁拟，结论就归谁**。topic 列表由 OpenAlex 维护，
  与本作品的主张无关，构成一个我们控制不了的采样框。

## 测量定义（写死）

对每个 topic 的 display_name `P`：

```
fulltext_loose        = works?search=P                              （全文宽松，不加引号）
title_abstract_phrase = works?filter=title_and_abstract.search:"P"  （短语）
title_phrase          = works?filter=title.search:"P"               （短语）
ratio                 = fulltext_loose / title_phrase
```

三个数一律同时报。**不许只报一个** —— 那正是本探针要防的事。

## 三态（承重点，与前五份预注册同构）

```
measured    title_phrase >= 10 且三次请求均成功    → 进统计
too_narrow  title_phrase < 10（含 0）              → 单独列出，**不并入任何统计**
error       任一请求失败                            → 单独计数，**不并入任何统计**
```

**`title_phrase == 0` 必须落进 `too_narrow`，绝不许当成"倍数无穷大"计入。**
把「我没测着」混进「它没有」，是本项目反复在抓的病；小分母让倍数剧烈抖动，那是噪声不是发现。
`too_narrow` 与 `error` 的条数必须与 `measured` 一起出现在结论里，不许只报好看的那部分。

## 仪器阳性对照（不过就整轮作废）

正式普查之前，仪器本身必须过这两关：

1. **单调性**：`fulltext_loose >= title_abstract_phrase >= title_phrase`。
   这是 OpenAlex 口径语义的定义性后果——宽松口径的命中集合包含收紧口径的。
   **若 measured 中违反率 > 5%，说明我们对口径语义的理解是错的，整轮作废**，
   而不是把违反的那些删掉再报。
2. **阴性对照**：至少要有一批 topic 的 ratio 落在**低倍数区**（< 100）。
   一个把所有短语都判成"差几千倍"的指标，分不出任何东西，与全判成 0 一样没用。
   **若 measured 中 ratio < 100 的比例为 0，整轮作废。**

## 预测（写在开查之前，可被推翻）

> 这四条是**预测**不是结论。任一条被数据推翻，如实记账，不改预测。

- **P1**：measured 的 **ratio 中位数 ≥ 100**。
- **P2**：measured 中 **ratio ≥ 1000 的占比 ≥ 10%**，即"差三个数量级"不是个别现象。
- **P3**：**ratio 的分布跨越至少 4 个数量级**（P95/P5 ≥ 10^4），即口径敏感度本身**因概念而异**——
  所以"报一个数就行"在任何单个概念上都不安全。
- **P4**：`too_narrow`（title_phrase < 10）占总体 **< 30%**。若超过，说明 topic 名普遍不是可用检索式，
  普查的外部效度要在结论里降级披露，**但不删数据**。

## 失败判据（整轮作废，退出码 2）

- 落盘 topic 条数 ≠ 开查时的 `meta.count`
- 单调性违反率 > 5%
- ratio < 100 的比例为 0（指标无区分度）
- API 失败率 > 5%
- 统计量与逐条原始数据对不上（判据会逐条复算，不看结论行）

## 明确不做的事

- **不解释因果。** 测到某 topic 口径差大，只说明**这个词在全文里比在标题里常见得多**，
  不说明该领域的文献量被高估了。这两句话差很远。
- **不给 topic 排优劣。** 倍数大不是缺点，是"这个词需要注明口径"。
- **不做跨时间比较。** 本轮是一个时间点的截面，OpenAlex 索引天天在长。
- 不用单词检索的结论替代短语检索（单词加引号会匹配词干变体，实测 `"synthesizability"`
  报 240 万篇，首条是 *…molecular sieves **synthesized** by…*）。

## 诚实边界（必须与结论一起出现）

- 测的是 **OpenAlex 一家的检索行为**，不是"文献计量学普遍如此"。换 Scopus/WoS 结论可能不同。
- topic 的 `display_name` 是 OpenAlex 编的标签（如 "Military Technology and Strategies"），
  **不必然是研究者真会输入的检索式**。这是本轮外部效度的主要限制，必须与数字同页出现。
- 全文口径（`search=`）在 OpenAlex 上宽松到何种程度没有公开文档，
  本轮只测其**后果**（命中数差多少），不主张知道其**机制**。
- 普查是全总体，所以**没有抽样误差**；但也因此**不存在置信区间**——
  数字就是这个时间点的事实，不许给它套统计检验来显得更科学。
