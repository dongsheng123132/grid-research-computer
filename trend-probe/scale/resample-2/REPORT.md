# 结论摘要

**未能判定。** 预注册的 2015–2024、n=500 重抽样尚未取得任何 OpenAlex 样本行：本执行环境的直连与代理 HTTPS 均失败。故不能声称 11,364 倍中位数或 85.7% ≥1,000 倍在新切片中成立或不成立；空结果没有被伪装为零。

## 1. 这次检验什么

原实验是在 OpenAlex 全历史索引、固定种子 `trend-scale-v2-20260824` 的 n=1,000 topic 随机样本上测得：measured 行的 ratio 中位数为 11,363.9，85.7143% 的 ratio 至少为 1,000；同时 73.4% topic 因标题精确短语命中少于 10 而是 `too_narrow`。

本轮按采数前已写入的 [PREREG-resample2.md](PREREG-resample2.md)，把三种查询口径均限制为发表年 2015–2024，并将种子改为 `trend-scale-resample2-20260902`。这不是仅换种子：它检验原发现是否依赖全历史索引的累积深度。抽样框仍为上级的冻结 `topics.json`（N=4,516，SHA-256 已预注册），目标样本为 n=500。

三口径及分类与原实验保持一致：全文宽松 `search=<phrase>`、标题+摘要精确短语、标题精确短语；三数均有效且标题命中不少于 10 才进入 `measured`，ratio 为全文宽松/标题精确短语。`too_narrow` 与 `error` 保留而不进入 ratio 统计。

## 2. 预注册判据

阈值已经固定，未因本次失败而修改：P1 中位 ratio ≥100；P2 measured 中 ratio ≥1,000 的比例 ≥10%；P3 中位数位于原实验的 0.5×–2×（5,682–22,728）；P4 `too_narrow` 占比在 50%–85%。比例须带有限总体校正的 95% Wilson 区间；单调性违反率或 API 失败率超过 5% 即作废。

## 3. 实际运行记录

没有发送任何样本查询，也没有生成任何样本行。开始完整 n=500 运行前，三种网络连通性测试均失败：Node 直连和经 `127.0.0.1:7897` 代理均为 `TypeError: fetch failed`；curl 经该代理为 `SEC_E_NO_CREDENTIALS`。可用的网页读取通道能读取基础 OpenAlex 端点，但会拒绝参数化检索 URL，不能用于采数脚本的替代执行。

[result-resample2.json](result-resample2.json) 如实保存该阻断状态、失败方式和空 `rows`；其中 `stats`、置信区间和预测结局均为 `null`，而不是 0。因而独立复算器 [verify-resample2.mjs](verify-resample2.mjs) 此时应失败（它要求完整、真实的 500 行），这是防止空数据误验收的设计结果。

因此，对“换了时间切片后，11,364 倍中位数和 85.7% ≥1,000 倍还成立吗？”的唯一诚实回答是：**当前尚无数据，不能判定。** 这既不是稳健性证据，也不是反证。

## 5. 可复跑方式与已知局限

在能访问 `api.openalex.org` 的环境中，从本目录运行：

```bash
node resample2.mjs
node verify-resample2.mjs
```

`resample2.mjs` 会读取本机 `.secrets/apikeys.env` 中可选的 `OPENALEX_API_KEY`，但从不输出密钥；每项最多重试五次、超时 40 秒、请求间至少等待 130ms。运行前应确认 OpenAlex 的可用额度：完整方案最多 1,500 个查询，超出预算或出现持续限流时应停止并将实际失败逐行保留，不应用旧数据填补。

即便完整运行成功，这仍只是 topic `display_name` 的随机样本，不是普查；它测的是 OpenAlex 在具体检索日期的行为，不能自动外推到 Scopus/WoS，也不能证明全文口径的内部匹配机制。
