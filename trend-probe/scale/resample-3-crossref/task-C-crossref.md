## 你的任务

用 **Crossref REST API**（`https://api.crossref.org/works`，完全免费、无需注册、无需 key，只需带一个 `mailto=` 参数走礼貌池即可，比如 `mailto=research@example.org`）复现同样的"检索口径敏感度"实验：

1. 先读 `../PREREG-v2.md` 和 `../REPORT.md`，搞清楚原实验具体怎么定义"全文宽松口径"和"标题短语精确口径"这两种检索方式、怎么算 ratio、怎么判定 too_narrow。
2. 设计一个 Crossref 版本的等价实验：
   - 抽样框：Crossref 没有 OpenAlex 那种 topic 分类体系，需要你自己设计一个抽样框——可以考虑从 Crossref 的 `works` 里按某个学科分类/关键词表随机抽一批"概念短语"，或者复用原实验 `topics.json` 里冻结的 4516 个 topic 短语作为检索词表（这些短语本身不是 OpenAlex 专有的，可以正当地在 Crossref 上原样检索）——用后者更省事也更能直接对比，推荐用这个。
   - 两种口径：Crossref 的 `query=` 参数（全文宽松，会匹配标题/摘要/作者等多字段）vs `query.title=`（仅标题字段精确短语匹配）——这是 Crossref 里最接近原实验"全文宽松 vs 标题短语"这个区分的两个参数。
   - ratio = 全文宽松命中数 / 标题精确命中数，同原实验；标题命中 <10 记为 too_narrow，不进入 ratio 统计。
3. **预注册先于数据**：把这次实验的判据、阈值、抽样量写成 `PREREG-crossref.md`（先写死再跑），可以参考 `resample-2/PREREG-resample2.md` 的结构。
4. 目标抽样量 n=500（若 Crossref 有限流/配额问题，如实报告实际能跑多少，不要为了凑够数字编数据；哪怕最后只跑成 100 条，也如实报告并说明为什么）。
5. 请求间隔至少 1 秒，遇到限流用指数退避重试，最终失败的记录如实标"查询失败"，不计入分母。
6. 跑完后计算 ratio 分布（中位数、超过 1000 倍的比例等），和原 OpenAlex 实验（11364 倍中位数、85.7%）做对照，回答："换一个完全不同的检索语料（Crossref vs OpenAlex），11364 倍中位数和 85.7% 超千倍这个"检索口径普遍存在巨大差异"的现象，是否在另一个语料里同样能看到（哪怕具体倍数不同）？"
