# 任务：trend-probe 口径敏感度探针 —— 换语料/换时间点重跑

## 背景

`trend-probe/scale/` 已经做过一轮口径敏感度实验：用 OpenAlex 检索，预注册抽样种子 `trend-scale-v2-20260824`，n=1000 随机抽样，测得口径倍数中位数 11364，85.7% 超过 1000 倍差异，4 条预注册预测里 2 条被推翻。这是本作品（GOAI 2026 AI4R 复赛「让『不存在』这一步可被检验」/取象/陈东）的第二条主证据线。

三位独立评审（含总指挥自己）一致认为：**只用一个随机种子跑一次，不足以说明这个"11364 倍口径差异"的结论对语料/时间点的选择是稳健的**——万一换个时间点、换个语料子集，倍数结构就变了，那说明这个发现依赖于这一次抽样的偶然性，而不是真的稳定现象。Codex 的独立评审明确建议：不要只是换随机种子重跑同一批数据，而要**真正换一个不同的时间点或不同的语料子集**，才能提供有意义的稳健性证据。

## 输入

- 现有代码与方法：`trend-probe/scale/REPORT.md`、`PREREG-v2.md`、`verify-trend-scale.mjs`，以及该目录下的抽样/检索脚本（请先读这些文件搞清楚原方法怎么做的：怎么抽样、怎么查 OpenAlex、口径倍数怎么算）。
- OpenAlex API 是免费的，匿名档有限额（本作品披露过 2026-08-24 后 $0.10/天=100 次的使用记录，注意控制请求量，不要超支）。

## 硬边界（不许碰）

- **只在新建的子目录 `trend-probe/scale/resample-2/` 里写文件**，不要修改或覆盖 `trend-probe/scale/` 下任何已有文件（`REPORT.md`、`PREREG-v2.md`、`verify-trend-scale.mjs` 等是已提交材料的一部分）。
- 不要 `git commit` / `git push`。不要删除任何文件。
- 不要伪造/编造 OpenAlex 查询结果——如果被限流或请求失败，如实记录，不要用假数据填充。

## 要求

1. 选一个和原方法**不同的时间切片或语料子集**（比如换一批不同的发表年份区间、或换一批不同学科分类的检索词样本——具体怎么换，你根据 `PREREG-v2.md` 里原来的抽样方法自己设计一个有意义的对照，并在报告里说清楚为什么这个对照能检验"稳健性"这件事）。
2. 保持和原实验一样的抽样规模量级（n 不需要严格等于 1000，但要足够大到能算出有统计意义的口径倍数分布——如果受限于 API 配额只能做到几百，如实说明并解释为什么这个规模仍然有参考价值）。
3. 预注册再跑：判据、阈值先写死在文件里，再跑数据，不能看到结果再回头改判据。
4. 计算口径倍数分布（中位数、超过 1000 倍的比例等，和原报告保持相同的统计口径以便对比），并**和原实验（11364 倍中位数、85.7%）做对照**，判断这次的结果是否指向同一个结论（"检索口径差异普遍且巨大"）还是出现了实质性偏离。

## 输出

在 `trend-probe/scale/resample-2/` 下写：
- `PREREG-resample2.md`：这次重跑的预注册（时间/语料切片怎么选的、n 是多少、判据和阈值）
- `REPORT.md`：方法、实际跑出来的数据、和原实验的对照表、结论（含如果结果不稳健也要如实写）、已知局限
- `result-resample2.json`：机器可读的完整数据
- 查询脚本（保证可复跑，写清楚怎么跑）

## 验收

- 数字必须是真实跑出来的，不是编的
- 报告要明确回答："这次换了时间/语料之后，11364 倍中位数、85.7% 超过 1000 倍这个结论还成立吗？"
- 完成后把最终结论（成立/不成立/部分成立，及关键数字）总结在 REPORT.md 开头的"结论摘要"里，不超过 200 字
